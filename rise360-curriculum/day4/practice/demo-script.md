# Live demo — build a complete course in 45 minutes

**Day 4, afternoon. Facilitator runs this on the projector; participants watch, they do not build along.**

This is the run sheet for the demo course *Feedback that lands* — two lessons, one quiz,
published and exported. Every word you need to type is already written below, so you never
compose copy in front of a room. Follow the run sheet in order and narrate as you go.

The whole point of watching rather than building along: participants see the **order of
operations**. They will build their own version for the capstone, and the order is the part
that is hard to recover from a slide.

---

## At a glance

| | |
|---|---|
| **Course** | Feedback that lands |
| **Shape** | 2 lessons + 1 quiz + a cover page |
| **Runs** | 45 minutes, including questions |
| **Ends with** | A live Quick Share link on screen, and a SCORM zip in the Downloads folder |
| **Uses today's blocks** | Button, Button stack, Scenario |
| **Uses all four question types** | Multiple Choice, Multiple Response, Fill in the Blank, Matching |

**Why this topic.** Everyone in the room has given feedback badly at some point, so nobody
gets stuck on the subject matter and everyone can judge whether the scenario rings true.
Swap the topic if your audience shares a better one — but keep the shape, because the shape
is what the capstone repeats.

---

## Before you start

Do all of this **before** the room fills up. Half of these have ruined somebody's demo.

- [ ] Sign in to Rise 360 and leave the dashboard open on the presenting screen.
- [ ] Close every other tab. Notifications off. Email quit, not minimised.
- [ ] Browser zoom at 100%, then press `Ctrl/Cmd +` twice — Rise's editor text is small from the back of a room.
- [ ] This file open on your second screen, ready to copy from.
- [ ] Search Content Library 360 for a character **once, now**, so the first search of the day is not live. Suggested filter: any character, business clothing.
- [ ] Have a **fallback course** already built and published, in case the network dies. Say so out loud if you have to switch to it — do not pretend.
- [ ] Delete last run's demo course, or rename it `Feedback that lands (old)`. Two courses with the same name on screen confuses everybody.

**One honest caveat, worth saying to the room once:** Articulate ships changes to Rise every
few weeks, and menu wording moves. If a label on screen differs from a label in these notes,
the screen is right. Point at it and carry on — that is a useful thing for them to see you do.

## The course blueprint

Show this before you touch the tool. Draw it on a whiteboard if you have one.

```
Feedback that lands
│
├─ Lesson 1 · Why feedback fails          (read — 5 blocks)
│    Heading → Paragraph → Statement A → Numbered list → Button
│
├─ Lesson 2 · Try it                      (do — 3 blocks)
│    Paragraph with heading → Scenario (3 scenes) → Button stack
│
└─ Quiz · Check yourself                  (score — 4 questions)
     Multiple Choice → Multiple Response → Fill in the Blank → Matching
```

Nine blocks and four questions. That is a real course, and it is small enough to build in
front of people. **Say the number out loud** — the most common capstone failure is scope, and
"nine blocks" is the anchor that prevents it.

## Run sheet

### 0 · Create the course — 3 min

| Do | Say |
|---|---|
| Dashboard → **Create** | "Everything starts here. One button." |
| Choose **Course** (not Microlearning) | "Microlearning is a single lesson and it cannot hold a quiz. We need a quiz, so: Course." |
| Skip the content templates → **Blank** (upper right) | "Templates are genuinely good. I'm starting blank so you can see every decision." |
| Type the title: `Feedback that lands` | "Name it like a promise to the learner, not like a filing reference. Not 'Module 3'." |
| Add a cover photo from the stock library — search `conversation` | "This is the one image most learners actually see." |

**Watch out:** if you land on Microlearning by accident you will discover it 20 minutes later
when the quiz option is missing. Check the top of the outline before you continue.

---

### 1 · Lesson 1, "Why feedback fails" — 10 min

Add a lesson: **+ Lesson** in the outline → name it `Why feedback fails` → open it.

Add five blocks. Use the **+** that appears between blocks each time, so the room sees where
new blocks land.

**Block 1 — Text › Heading**

```
Most feedback fails before it is given
```

**Block 2 — Text › Paragraph**

```
People do not reject feedback because it is critical. They reject it because it arrives as a verdict on who they are, with no evidence and no way forward. Three small changes fix almost all of it: name the behaviour, name the effect, and agree one next step.
```

**Block 3 — Statement › Statement A**

```
Describe the behaviour, not the person.
```

> Narrate the swap here: click the block, use the block-type switcher, and flip Statement A
> to Statement C and back. "Same content, different emphasis, no retyping. This is why you
> pick the family first and the variant last."

**Block 4 — List › Numbered list**

```
1. Name the behaviour. What you saw or heard, not what you concluded.
2. Name the effect. What it cost — time, trust, a customer, a deadline.
3. Agree the next step. One thing, and who does it.
```

**Block 5 — Interactive › Button**

- Button text: `Open the one-page feedback template`
- Destination: **Link to a webpage**
- URL: your real template, or `https://articulate.com` for the demo

> Point at the label. "'Click here' would have told them nothing. The label says exactly what
> happens." Then open **Settings** on the block and show the four things worth changing —
> colour, alignment, corner radius, width — and the one you cannot: **button text size**.
> Somebody always asks.

**Close the lesson.** Point out the lesson is now in the outline with an estimated duration.

---

### 2 · Lesson 2, "Try it" — 12 min

This is the centrepiece. Slow down.

Add a lesson named `Try it`.

**Block 1 — Text › Paragraph with heading**

```
Heading: Now you try
Paragraph: Priya missed a deadline that held up two other people. She has not mentioned it. You have five minutes with her at her desk. Work through the conversation and see where each choice lands.
```

> Say why this paragraph exists: **a scenario with no lead-in gets scrolled past.** The block
> above it tells the learner what they are about to do and why.

**Block 2 — Interactive › Scenario**

Build it in this order, narrating each part:

1. **Background** — Content Library 360, search `office`. Pick a landscape image. Mention that portrait images get cropped hard, and that the blur is a toggle if the background is fighting the text.
2. **Character** — photographic characters only. Filter and pick one. "You get poses, not expressions you can dial in. Choose the character whose poses cover the range you need."
3. **Scene description** — Rise asks for one and you should write it: it is what a screen-reader user gets instead of the picture.
   ```
   Priya at her desk in an open-plan office, looking up from her screen.
   ```

**Scene 1 — Dialogue**

```
Character says: Oh — hi. Did you need something?
```

Three responses (three is the maximum a dialogue takes):

| Response the learner picks | Feedback the character gives | Go to |
|---|---|---|
| `The spec was two days late and it held up Dan and me. Can we work out what happened?` | `Yeah. I got stuck on the pricing section and didn't want to send something half-finished. I should have said so on Monday.` | Scene 2 |
| `We need to talk about your reliability.` | `...Right. Okay. What do you want me to say?` | Scene 3 |
| `No, all good! Just checking in.` | `Great — I'm heads-down on the launch, so I'll crack on.` | Scene 3 |

**Scene 2 — Dialogue** (the productive branch)

```
Character says: So what would help?
```

| Response | Feedback | Go to |
|---|---|---|
| `Flag it the same day you get stuck. I'd rather see something half-finished on Monday than nothing on Wednesday.` | `That I can do. Monday, even if it's rough.` | Scene 4 |
| `Just try to be more organised.` | `Sure. I'll try.` | Scene 3 |

**Scene 3 — Text** (the reset)

```
That closed the conversation instead of opening it. A verdict invites defence; an observation invites explanation. Try the opening again.
```

Set **Go to → Try again**.

> This is the slide-worthy moment. Say it plainly: *"Try again is the difference between a
> scenario and a trick question. It sends them back to the decision, not to a scolding."*

**Scene 4 — Text** (the ending)

```
Behaviour named, effect named, one next step agreed — and Priya proposed it herself. That is the whole method.
```

Set **Go to → End Scenario**.

**Block 3 — Interactive › Button stack**

Two buttons:

| Text | Destination |
|---|---|
| `Take the check` | **Navigate to Another Lesson** → the quiz |
| `Read the template again` | **Navigate to Another Lesson** → Lesson 1 |

> "A button stack is how you offer a route without taking navigation away from anyone. Nobody
> is trapped, and the learner who wants a second pass gets one." Show the **spacing** setting,
> which only stacks have.

**Preview the scenario now**, in front of the room, and deliberately take the rude branch so
they see Try again fire.

### 3 · The quiz — 8 min

Outline → **+ Quiz** → name it `Check yourself`.

One question of each type. Read each stem aloud as you add it.

**Q1 — Multiple Choice**

```
Stem: What should the first sentence of feedback do?

  Name a specific behaviour the other person can picture.   ← correct
  Summarise your overall opinion of their performance.
  Ask how they think things are going.
  Soften the message with a compliment first.

Feedback (correct): It gives them something concrete to respond to.
Feedback (incorrect): Openings that generalise put people on the defensive before you reach the point.
```

**Q2 — Multiple Response**

```
Stem: Which of these belong in useful feedback? Select all that apply.

  The behaviour you observed.      ← correct
  The effect it had.               ← correct
  One agreed next step.            ← correct
  Your assessment of their character.
  A list of everything else they have got wrong this year.
```

**Q3 — Fill in the Blank**

```
Stem: Describe the ________, not the person.
Accepted answer: behaviour
```

> Show the **accepted answers** field and add `behavior` as a second accepted spelling.
> "Fill in the Blank matches text. If you do not add the variants, you will fail people for
> being American."

**Q4 — Matching**

```
Match the opening line to the problem with it.

  "You're always disorganised."          →  Judges the person, not the behaviour
  "Someone mentioned there was an issue." →  No evidence the person can act on
  "Great job, but..."                     →  Buries the message
  "We need to talk."                      →  Creates fear without information
```

**Now open quiz Settings** — this is the part people forget exists. Walk the list and change
exactly two things, so they see cause and effect:

| Setting | Default | Set to | Why |
|---|---|---|---|
| Passing Score | 80% | 75% | "Four questions. 80% means you must get all four — there is no such thing as 80% of four." |
| Shuffle Answer Choices | Off | **On** | "Stops people memorising position." |
| Randomize Question Order | Off | leave off | "With four questions it just makes support harder." |
| Quiz Retries | Unlimited | leave | — |
| Reveal Answers | — | Show incorrect answers with feedback | "The feedback you wrote only gets read if you let it show." |
| Require Passing Score to Continue | Off | leave off | Mention it exists and is a gate. |

### 4 · Preview like a learner — 5 min

**Preview**, then click through all five device views: desktop, tablet portrait, tablet
landscape, mobile portrait, mobile landscape.

Land on **mobile portrait** and stay there for a moment.

> "This is where most Rise courses are actually taken, and it is where the demo usually finds
> a bug. Watch the button stack — do the labels still fit? Watch the scenario — is the
> character crowding the text?"

Fix whatever it shows you, live. **Do not skip this even if it looks fine** — the point is
the habit, not the fix.

### 5 · Publish and export — 7 min

Click **Publish**, top right. Take the four doors in this order.

**Quick Share** — do this one for real.

- Turn the **Guestbook** off for the demo ("on by default; it asks every learner for a name and email").
- Turn **live updates** on. Then, with the link open in a second tab, change a word in Lesson 1 and refresh. That single move sells the feature better than any slide.
- Copy the link and paste it into the chat or channel. **The room now has your course on their phones.** Let them open it.
- Note the ceiling honestly: Quick Share gives you views and guestbook entries. It does not give you per-learner quiz scores.

**LMS** — do this one for real too, and let the download finish on screen.

- Standards: xAPI (Tin Can API), SCORM 2004, SCORM 1.2, AICC, cmi5. Pick **SCORM 1.2** and say why: "it is the one that works everywhere, and it is what most of you will be asked for."
- Tracking: completion percentage / Storyline block / **quiz result**. Choose quiz result.
- Say the sentence that matters most in this whole section: **only a Quiz lesson reports a score. Knowledge Check blocks never do.** People build a course of knowledge checks and then wonder why the LMS shows nothing.
- Show the zip land in Downloads. Do not try to upload it to an LMS live.

**Reach 360** — describe, do not demo, unless your organisation uses it. "Articulate's own LMS, publishes straight from here, best when your learners are outside the company and will never have a corporate LMS account."

**Web / PDF** — describe. Web gives you a zip you host yourself, launched from `index.html`, with no tracking at all. PDF flattens the course into a document; every interaction becomes a static picture. "PDF is a reference handout. It is not a course."

> If somebody asks why LMS and Web are greyed out on their account: those two paths need a
> standard Articulate 360 licence. Quick Share and PDF do not.

## Three mistakes to make on purpose

Scripted failure teaches faster than success, and it makes the room relax. Do all three.

1. **Add a block in the wrong place**, then drag it. Recovering gracefully from a misplaced block is the single most reassuring thing you can show a nervous beginner.
2. **Write a scenario response as a trick** — add a fourth option that is obviously stupid, look at it, and delete it. Say: "If the wrong answer is obviously wrong, the learner has not made a decision. Every option has to be something a real person would actually choose."
3. **Set the passing score to 80% with four questions**, let somebody in the room work out that this means 4/4, then fix it. This lands harder than telling them.

## Questions you will get, with answers

**"Can I stop them skipping ahead?"**
Yes — course navigation can be set to restricted, and quizzes have *Require Passing Score to
Continue*. Both are Day 5 territory; say that and move on.

**"Can the scenario score?"**
No. Scenario is practice, not assessment. If you need a score, that is a quiz.

**"How many scenes should a scenario have?"**
Fewer than you want. Three to five decisions is plenty. The cost is in writing the branches,
not in adding scenes.

**"Can I reuse this course for another team?"**
Yes — duplicate it from the dashboard, or use *Send a copy*. Blocks can be saved as block
templates and reused too.

**"What happens to my Quick Share link if I edit the course?"**
With live updates on, the link shows the new version immediately. The link itself only dies
when you delete the training or the subscription lapses.

**"Why can't I make the button text bigger?"**
You can't. It is a real limitation, not a setting you have missed.

---

## If it breaks

| What breaks | What you do |
|---|---|
| Rise is slow or the editor stalls | Stop talking about it. Switch to the pre-built fallback course and keep the narration going. |
| Content Library search returns nothing | Upload a background from your local folder — have one ready. |
| The Quick Share link will not open on their phones | Show it on your own screen and move on. Do not spend the room's time debugging Wi-Fi. |
| A setting is not where these notes say | Say "they've moved it — this is why we check the live interface," find it, carry on. This is a feature of the demo, not a failure. |
