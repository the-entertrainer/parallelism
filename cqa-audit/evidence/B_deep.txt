[H2] Introduction to In Person Payments 

PayPal's in-person payment solutions let businesses accept payments at a physical location — whether that's a shop, market stall, or mobile service — all managed from a single PayPal business account alongside any online sales. There are different options, ranging from zero hardware (QR codes, Tap to Pay) to dedicated card readers and full point-of-sale (POS) terminals, so businesses of any size can find a fit. Let's look at the PayPal POS system. 

[BLOCK image] PayPal POS System (Zettle) 
Zettle is PayPal’s POS solution used by businesses to accept in-person payments . It includes both hardware and software , such as card readers and payment tools . Zettle is being rebranded to PayPal POS, although the Zettle terminal will still appear on our website. 
While PayPal is widely recognized for online payments , its vision is to be more than just a button at checkout . To achieve this, PayPal also offers in-store payment solutions that support businesses selling in person, expanding its role beyond digital transactions. 
Within Spark, teammates can view whether a merchant has applied for, activated, or deactivated Zettle services on their PayPal account via the Zettle workflow . This visibility helps teams better support merchants in managing their POS solutions .

%%%%%%%%%%%% API and Integration %%%%%%%%%%%%

[BLOCK text] Now let's understand what API is and how an API connects merchant products to PayPal. We will also go through a basic PayPal Checkout example so you can relate the concept to a real-world business scenario. 

[BLOCK text] 
[H2] Why This Matters 

When two systems need to work together, they typically do not share a screen or a database directly. Instead, they communicate through an API, which acts as a secure gateway that receives a request, processes it, and returns a response. 
Simple Analogy: An API works as a waiter in a restaurant. Your app places an order, the waiter delivers it to the kitchen, and the kitchen prepares the request and sends back the result. 
Business Example: An e-commerce website can use the PayPal API to create an order, redirect the buyer for payment approval, and then capture the payment once it is approved. 

[BLOCK image] How APIs Work 
The following steps explain how an APIs works: 

• Request: The application sends a request to a specific endpoint, including details such as the item, amount, or customer action. 

• Authentication: The receiving service verifies that the request is coming from an authorized application, often using a secure token. 

• Processing: The server processes the request based on business rules, such as validating data or confirming whether a payment can be completed. 

• Response: The API returns a response, usually in JSON format, so the application understands the outcome and next steps. 

[IMG alt=""] 
[BLOCK text] 
[H2] Typical API Flow 

The following steps represent a standard API exchange : 

• Client API: The user clicks “Pay with PayPal.” 

• API Request: The application sends the order details to PayPal. 

• API Response: PayPal responds with an order ID and an approval link. 

• User Action: The buyer reviews and approves the payment.

%%%%%%%%%%%% PayPal Payment Flow %%%%%%%%%%%%

[BLOCK image] PayPal Payment Flow 
A typical PayPal checkout process begins when a buyer selects PayPal as the payment method. The merchant then creates an order, the buyer approves the payment on PayPal, and finally, the merchant captures the payment to complete the transaction. 
[IMG alt=""] 
[BLOCK text] 
[H2] End-to-End Process 

Here's how a PayPal-powered checkout works, from order creation to payment capture: 

• Create Order: The application sends product and pricing details to PayPal 

• Return Order ID: PayPal returns an order ID along with an approval path 

• Buyer Approval: The customer chooses PayPal or a card and confirms the payment 

• Capture Order: The application instructs PayPal to capture the funds and finalize the purchase 

[BLOCK text] 
[H2] Key Terms 

Here are a few key terms along with their definitions: 

[BLOCK text] Endpoint 
A URL that performs a specific function, such as creating or capturing an order. 
OAuth Token 
A temporary token that verifies the application is authorized to access the API. 
JSON 
A structured data format used to exchange requests and response data. 
Capture 
The step where the payment is finalized and funds are secured. 

[BLOCK text] 
[H2] Security and Best Practices 

Payment API should never be treated like open or public links. Sensitive information, such as credentials, must always be protected. Secrets should remain on the server side, and every request must be authenticated before performing critical actions. 
Do: Safely manage client IDs and secrets, exchange them for access tokens, and limit token usage to necessary actions. 
Do Not: Expose secrets in front-end code or assume a payment is complete before the capture step is successfully completed. Why this matters in training: 
Even non-technical teams benefit from understanding this flow because it explains why engineers ask for credentials, sandbox testing, approval redirects, and post-payment confirmation. 

[BLOCK text] 
[H2] Types of API 

There are two types of API that merchants can use to integrate their PayPal account with an eCommerce website: 

• Classic API 

• REST API 

A merchant can choose only one type for integration. 
Classic API REST API Before adopting Classic APIs, understand their capabilities and limitations: 

• This is the older version of PayPal API. 

• It offers two authentication methods: Signature and Certificate. 

• These API are accessed directly from the PayPal account. 

• They are not compatible with newer checkout features such as Pay with Venmo, Pay in 4, or cryptocurrency payments. 

Unlike Classic APIs, REST APIs are fully equipped for modern payment experiences — here's what sets them apart: 

• This is the latest and recommended version of PayPal API. 

• It uses Client ID and Secret for authentication. 

• These credentials are managed through the PayPal Developer platform. 

• It supports modern checkout features, including Pay with Venmo, Pay in 4, and crypto payments. 

• It also provides a sandbox environment for testing integrations before going live.
